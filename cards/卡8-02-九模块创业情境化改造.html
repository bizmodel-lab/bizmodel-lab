九模块创业情境化改造

九个模块、九条初创规则——把通用画布改造成贴合创业情境的动态工具。

为什么需要这张卡

商业模式画布（BMC）是通行的描述工具，但创业者拿到的往往只是一张"填空表格"——九个格子填满了，创业的关键难题却一个都没解决。教材在介绍画布之后，针对初创期的动态情境，对九个模块逐一给出了操作规则：什么时候该小、什么时候该专、什么时候该外包。

这张卡把这些规则从教材中抽出、集中成一张"画布使用说明书"，带来三层实践价值：

从填表到决策
每个模块附判定规则，填完即可自查对错，而不是填完就束之高阁。
适配初创情境
规则针对资源少、不确定性高的创业阶段，教你在约束下取舍。
连成整体视角
九模块归入价值端与交付端两簇，一眼看清模式的两条主线。

价值端与交付端逐模块详解

价值端

聚焦价值的传递与获取

五个模块：细分 / 主张 / 渠道 / 关系 / 收入
价值端回答的是："价值如何送达客户、又如何变成钱？"
客户细分
用递进式细分对抗贪大：先服务一个极端用户群体，跑通后再扩圈。细分的三类错误见下方警示区。
价值主张
按三层面递进打磨：从产品核心特征，到相对竞品的独特优势，最终落到用户的实际利益——客户买单的是最后一层。
渠道通路
在控制力与覆盖度之间做权衡：自建渠道掌控强但烧钱，借力渠道铺得快但命脉在别人手里；每条渠道都要测算投入产出比。
客户关系
沿关系递进路径升级：交易 → 社群 → 专属 → 共创。初创期不必一步到位，但要清楚当前停在哪一级、下一级靠什么爬上去。
收入来源
警惕收入模式单一的误区——所有收入押在一个来源上，来源一断模式即停；定价与付费方式用 A/B 测试验证支付意愿，不靠猜。
客户细分的三类错误
细分过宽"所有年轻人都是我的用户"——等于没有用户，验证无从下手。
细分过窄锁定的群体太小，即便全部拿下也撑不起模式。
细分错位把"买单的人"和"用产品的人"混为一谈，主张打错了对象。
交付端

聚焦价值的创造

四个模块：资源 / 业务 / 伙伴 / 成本
交付端回答的是："价值靠什么被实际做出来？"
核心资源
逐一识别哪些资源缺失会导致整个模式停摆——这类资源应优先内部构建，而不是外包或租用。
关键业务
只把与核心竞争力直接相关的活动留在手里，其余外包。初创公司最容易死于"什么都自己干"。
合作伙伴
按资产专用性设计治理机制：对方投入的资产越专属、越难挪作他用，越需要用合同条款把权责利锁定清楚。
成本结构
先判断自己是成本驱动型还是价值驱动型，再引入单位经济（UE）视角：算单个客户的账，而不是只算总账。
两端的共同健康标准
匹配与平衡教材的判定原话：价值端与交付端保持匹配与平衡。主张端许诺了高端体验，交付端却只有低成本产能，即为失衡。

怎么用这张卡

  1. 先铺底。用画布把九模块现状如实填出来，每格一句话即可；不确定的内容照填，但用红黄绿灯标注确信度（做法见卡 8-03）。
  2. 逐条对照。拿本卡九条情境化规则逐模块自查：细分是否犯了三类错误？主张是否停在特征层没落到利益层？收入是否单一？
  3. 标红修正。命中的问题按优先级处理——客户细分与价值主张两格优先：这两格错了，后面七格都是白干。
  4. 极端用户切入。如果细分过宽，立刻收窄到一个极端用户群体，把"验证成功后再扩大"写进计划，而不是嘴上说说。
  5. 定期复检。模式任何模块发生调整后，把九条规则重新过一遍——画布是动态文件，规则也要动态执行。

适用场景与边界

适用

  • 初创团队第一次画商业模式画布：填格之前先读规则
  • 早期项目的客户、渠道与收入设计：规则全部针对初创动态情境
  • 项目"跑不通"时的逐模块复盘：一条规则一条线索地排查
  • 创业培训中的画布教学：规则即课堂上的判定标准

慎用与注意

  • 画布本体是奥斯特瓦德的工具，引用时须注明来源；本卡规则是教材叠加的情境化改造
  • 规则针对初创情境，成熟企业的九模块用法（如多元业务、事业部结构）需另行分析
  • 画布是描述与设计工具，不是验证工具——格子里写得再对，也要靠验证流程检验（卡 8-13、卡 8-14）
